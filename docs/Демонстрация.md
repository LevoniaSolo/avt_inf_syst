# Как показать «Опекс»

Из корня проекта выполните `bash run-demo.sh` и откройте `report.html` по пути из последней строки. Учебный пример работает с локальными данными. Для проверки на реальных отчётах есть отдельная команда в [README](../README.md).

## Объяснение на две минуты

1. **Откуда берутся данные.** Аналитик даёт список компаний и настройки. Система получает дневные котировки с указанных площадок. Отчётность Yahoo Finance может скачать сама. Для Мосбиржи можно передать подготовленный CSV с отчётностью.
2. **Как данные становятся сопоставимыми.** Система проверяет тикер, валюту, дату и единицы измерения. Суммы в тысячах или миллионах приводит к единицам валюты. Например, выручка отдельного второго квартала равна выручке за полугодие за вычетом первого квартала. Каждая цифра связана с исходным полем и формулой. Пропуск отображается вместе с причиной.
3. **Что видит аналитик.** Скринер показывает компании, прошедшие условия отбора. В карточке можно сверить расчёт. Для DEMO01 в квартале 31.03.2025 EBITDA равна 260,28, поскольку к операционной прибыли 189,28 прибавилась амортизация 71. Два P/E используют одну капитализацию и разные периоды прибыли. Расхождение 24,46% превышает порог ТЗ в 20%.
4. **Где машинное обучение.** Модель учится на ряду прошлой выручки и продолжает найденную линию на один период вперёд. При проверке очередную известную точку временно оставляют за пределами обучения и сравнивают прогноз с уже известным фактом. Naive для той же проверки повторяет последнее значение выручки. Чем меньше средняя процентная ошибка MAPE, тем точнее модель на выбранных точках.
5. **Что показывает сценарий.** Аналитик задаёт изменение выручки, маржи и долга. Система пересчитывает показатели с этими условиями и выводит две колонки, базу и сценарий. База сохраняет опубликованные значения.

Учебный отчёт показывает работу всех функций. В отдельном онлайн-прогоне проверены пять реальных бумаг. Квартальная оценка прогноза получена на четырёх контрольных точках. [Результаты проверки](Проверка.md).
